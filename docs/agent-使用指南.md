# Agent 使用指南

这个仓库可以直接作为本地知心伙伴工作区使用。它不要求接入其他记录系统：你手工写下的 Markdown 和主动保存的 Agent 会话，就是全部输入。

## Quick start：纯聊天法

在仓库目录启动你使用的 Agent：

```bash
claude
```

或：

```bash
codex
```

启动后把它当作 chatbot，直接聊你想聊的事情。一次会话结束时，可以说：

> 将本次会话全文保存到 L4，文件名使用日期、时间和简短主题。

以后开始新会话时，可以要求 Agent 先检索过去的信息，再接着聊：

- “搜索过去关于这件事的会话，结合当时的原话和我继续聊。”
- “先读取最近三次相关会话，告诉我有哪些变化。”
- “只读取最新一条相关记录，我想从那里接着谈。”

这种方式启动最快，但 L4 记录带有对话加工后的内容。若希望 Agent 更贴近事情发生时的真实状态，优先使用下面的 L0 人工记录法。

## 最推荐：L0 人工记录法

每次出现值得保留的事情、想法或感受，及时写入当天文件，例如：

`L0/2026-07-29.md`

不必追求完整文章。优先记录第一手信息：

- 发生了什么，以及大致时间和情境。
- 自己当时说了什么、做了什么。
- 当时的想法、情绪和身体感受。
- 哪些是已确认事实，哪些只是自己的判断或猜测。

在和 Agent 交流时，可以直接说：

- “读取今天的 L0，和我聊聊今天的事情。”
- “读取 7 月 20 日到 7 月 29 日的记录，这件事有什么连续变化？”
- “只读取今天最新几条，我想谈谈。”
- “比较过去一周和前一周，我有哪些变化？请同时找反例。”
- “回到相关 L0 原文，检查我们以前的判断现在是否仍然成立。”

## L1～L4 如何分工

| 目录 | 放什么 | 常见请求 |
| --- | --- | --- |
| `L0/` | 用户手写的第一手现场记录 | “读取今天的 L0” |
| `L1/` | 一整天材料的整理和压缩 | “把今天的 L0 和会话整理成一份日志” |
| `L2/` | 跨日期、围绕一个主题的完整脉络 | “整理我与某人的相处变化” |
| `L3/` | 多次材料支持的概念、模式、工具和方法 | “把这个反复有效的方法沉淀到 L3” |
| `L4/` | 单次 Agent 会话全文、摘要或工作包 | “保存本次会话” |

让 Agent 将一天的 L0 和 L4 整理到 L1 时，可以说：

> 整理今天的材料并写入 L1。区分事实、我的感受、我的解释和你的推测；保留来源文件，不要覆盖 L0。

整理跨日期专题到 L2 时，可以说：

> 检索与这个主题有关的 L0、L1 和 L4，按时间整理到 L2。列出变化、反例和仍不确定的地方，不要把相似直接当成同一模式。

只有当一个理解被多次材料支持、未来还会反复使用时，再让 Agent 把它整理到 L3。L3 仍是可修订的理解，不是对自己的永久定性。

## 隐私与备份

L0～L4 默认被 `.gitignore` 排除，不会进入这个公开仓库的 Git 提交。不要使用 `git add -f` 强行提交私人记录，也不要把它们推送到公开 fork。

被 Git 忽略也意味着这些记录不会自动备份。请使用你信任的本地备份、加密同步或私人仓库单独保存；备份方式与知心伙伴本身没有依赖关系。

如果需要用私人 Git 仓库保存 L0～L4，请先确认远端确实是私有仓库并与本公开仓库断开，再删除 `.gitignore` 中对应的 L0～L4 规则。不要在仍指向公开远端时解除忽略。
